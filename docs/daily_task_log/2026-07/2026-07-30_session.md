### 왜 했나요?
지금까지는 링크를 먼저 저장한 다음, 목록으로 돌아가서 카드의 `⋯` 메뉴를 열고 "컬렉션으로 이동"을 한 번 더 눌러야 했습니다. 저장할 때 이미 "이건 개발 폴더에 넣어야지"라고 생각하고 있는데, 그걸 앱에 알려줄 방법이 저장 화면에 없었던 셈입니다. 사용하시다가 직접 불편을 느껴 요청 주신 부분입니다.

### 오늘 알게 된 재미있는 사실
막상 열어보니 **앱 내부는 이미 이 기능을 받아들일 준비가 끝나 있었습니다.** 링크 정보에 "어느 컬렉션 소속인지"를 담는 칸도 있었고, 저장할 때 그 값을 함께 넘기는 배관도 이미 연결돼 있었습니다. 딱 하나, **그 값을 채워 넣을 화면 요소(버튼)만 없었습니다.** 그래서 데이터를 다루는 부분은 한 줄도 건드리지 않고 화면 쪽만 연결해서 끝났습니다 — 처음 예상보다 훨씬 작고 안전한 작업이 됐습니다.

### 오늘 변경된 것 (쉬운 말로)
1. **링크 추가 화면에 컬렉션 칸 추가**: 메모 칸 아래에 `📁 컬렉션 — 없음 ▸` 줄이 생겼습니다. 누르면 컬렉션 목록이 아래에서 올라오고, 고르면 그 이름이 표시됩니다.
2. **편집 화면에도 자동 적용**: 추가 화면과 편집 화면이 같은 부품을 쓰고 있어서, 이미 저장한 링크의 컬렉션을 바꿀 때도 같은 방식으로 동작합니다. 다른 앱에서 '공유'로 넘어와 저장하는 경로도 같은 화면이라 함께 됩니다.
3. **목록 화면의 기존 기능을 재활용**: 컬렉션 고르는 창은 이미 홈 화면에 있던 것을 꺼내서 공용 부품으로 만들었습니다. 새로 만들지 않았으니 두 화면의 사용감이 어긋날 일이 없습니다.
4. **컬렉션이 하나도 없을 때 안내 문구**: 예전에는 빈 공간만 보였는데, 이제 "컬렉션이 없어요"라고 알려줍니다.
5. **새 컬렉션 만들기는 이번에 넣지 않았습니다**: 저장 화면에서 폴더까지 새로 만들 수 있게 할지 여쭤봤고, 이번에는 고르기만 하기로 정했습니다. 만들기는 컬렉션 탭에서 그대로 가능합니다.

## 오늘의 학습

### 새로 배운 것
- **기능 요청 견적 전에 mutator 호출처부터 센다**: 상태 필드·엔티티·submit 경로가 이미 있는데 `updateX()` 호출처가 **테스트에만** 있으면 그건 미구현이 아니라 배선 누락이다. `grep -rn "updateCollectionId" --include=*.dart lib test` 한 번이 "데이터 레이어 설계"를 "위젯 1개 + 재사용"으로 축소시켰다. 어제(07-28) 알림 건의 "읽기만 있는 feature는 insert 주체를 찾아라"와 같은 계열의 판별법 — **한쪽 끝(쓰기/호출)을 grep하면 기능의 실제 상태가 나온다.**
- **AAB 버전은 merged manifest로 실측한다**: `.aab` 안 `base/manifest/AndroidManifest.xml`은 protobuf라 `strings`로 versionName·applicationId 같은 **문자열만** 보이고 versionCode(정수)는 안 나온다. bundletool 없이는 `build/app/intermediates/merged_manifests/prodRelease/processProdReleaseManifest/AndroidManifest.xml`(평문 XML)에서 읽어야 한다. pubspec 값 신뢰 금지 — `local.properties` 캐시 드리프트 전례가 있다(`b1cb04c`).
- **`jarsigner`의 PKIX 경고는 정상 출력**: `jar verified`와 `PKIX path building failed`가 동시에 나오는데, 후자는 self-signed 업로드 키라서 체인 검증이 안 되는 것뿐이다. 유효 판정 근거는 `jar verified` + `CN=`. 경고 문자열만 보고 실패로 보고하면 오독이다.
- **`null` 결과가 두 가지 의미를 가지면 래핑한다**: 피커에서 "'없음' 선택"과 "시트 닫기"가 둘 다 `String?` `null`이 되면 구분이 불가능하다. `CollectionPick` 래퍼 하나로 "닫으면 기존 선택 유지"라는 정상 동작이 성립했고, 테스트로도 고정했다.
