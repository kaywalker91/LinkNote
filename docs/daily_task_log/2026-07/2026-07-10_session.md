## 오늘의 학습

### 새로 배운 것
- **client cascade는 조인 행만 지운다 → 고아 정리는 DB 트리거 몫**: FK `ON DELETE CASCADE`는 M:N 조인의 연결 행만 제거하고, 참조가 끊긴 부모(tags) 행은 남긴다. 부모 청소를 원하면 `AFTER DELETE` **row** 트리거(cascade 삭제에도 발화)가 정석. UI 회피(inner join)와 DB 원천 정리는 별개 계층 — 둘 다 필요.
- **정리 트리거가 있으면 클라이언트 sync는 add-before-remove**: "전체 delete → insert" 패턴은 트리거가 유지 대상을 순간 0-참조로 오판해 삭제 → 재삽입 FK 위반. upsert(멱등 PK)로 유지분을 먼저 확정하고 stale만 삭제해야 안전. 트리거 없이도 무해한 개선이라 선반영이 정답.
- **postgrest-dart `.not(col,'in',v)` 값 형식**: PostgREST 원형 `col=in.(a,b)`라 `.not`의 value는 `'(${ids.join(",")})'` 문자열. `inFilter`(List)와 달리 `.not`은 자동 포맷 안 함. UUID는 특수문자 없어 무따옴표 안전.

### 심화 학습 추천
- **datasource fluent-builder 테스트 부재를 정직하게**: 이 repo는 postgrest 빌더 체인을 모킹하지 않고 에러/순수함수 경로만 단위 테스트. select 문자열·`_syncTags` 순서 검증은 brittle 모킹 대신 실기기 검증으로 대체함을 명시(허위 커버리지 방지).
